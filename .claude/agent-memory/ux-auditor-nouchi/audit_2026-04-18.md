# Audit initial — 18 avril 2026

## Frictions bloquantes confirmées
- P2 : `/proposer` redirige vers connexion SANS expliquer pourquoi ni montrer un aperçu du formulaire. Moussa abandonne avant de voir la valeur.
- P5 : Aucun CTA "Proposer un mot" sur la homepage dans le hero. Le parcours contribution est invisible au premier contact.
- Fiche mot : aucun bouton de partage sur `/mots/[slug]`. ShareButton existe mais n'est utilisé que sur la page de succès de /proposer.

## Frictions critiques confirmées
- Homepage `force-dynamic` : 3 requêtes DB en cascade (db.mot.count + getPopularMots x2 + db.user.count + db.voteMot.count). Moussa sur 3G voit un blanc.
- VoteSection fait un fetch client au montage pour chaque fiche mot visitée — coût réseau additionnel sur mobile.
- OpenGraph image des fiches mot : fond noir uni, pas de couleur identitaire, police system-font (pas de font custom dans ImageResponse).
- Métadonnées blog : pas d'image OG dynamique (pas de opengraph-image.tsx pour /blog/[slug]).
- Navigation "À propos" : typo dans navLinks ("A Propos" sans accent).

## Irritants confirmés
- Recherche : placeholder hero "Ex: goumin, choco, garba" mais la recherche s'ouvre en modal (pas inline). Confusion pour Moussa qui cherche à taper directement.
- kbd "⌘K" visible sur mobile dans le hero search — inutile et confus pour un utilisateur Tecno Android.
- Fiche mot : aucun "Proposer un mot" CTA sous la définition quand related words est vide.
- Fiche mot : WordInteractions (vote + commentaires mock) n'est PAS utilisé dans la page — remplacé par VoteSection. Composant mort dans le codebase.
- Filtre par lettre `/mots/lettre/[lettre]` : pas de navigation prev/next entre lettres, juste "Voir toutes les lettres".
- share.ts : getShareUrl ajoute `?vote=1&utm_source=share` — le paramètre vote=1 n'est géré nulle part dans le code de la page, friction potentielle.

## Ce qui fonctionne bien
- OG image dynamique sur /mots/[slug] via opengraph-image.tsx (Next.js ImageResponse, ISR 3600).
- ShareButton complet : native share, WhatsApp, X, copy — bon coverage.
- Formulaire /proposer : validation Zod, preview live, confirmation avec partage post-submit.
- Page connexion : Google SSO en 1 clic, pas de friction.
- Fiche mot : breadcrumb lettre, mots similaires par catégorie, date visible — Yao peut citer.

**Why:** Première session d'audit — base de référence pour tous les audits futurs.
**How to apply:** Ne pas ré-auditer les points résolus. Vérifier le statut de chaque friction avant de signaler à nouveau.
