**Date :** 2026-04-17
**Verdict :** 🟡 RECALIBRAGE
**Raison principale :** VoteSection activée et visible publiquement alors que le seed éditorial est à 0 mot validé en DB (données encore inexistantes en production). Risque de "dictionnaire vide qui paraît faux".

**Mots validés en DB au moment de l'audit :** 0 (base de données non seedée — toutes les routes lisent depuis Prisma, pas de fichier words.ts, donc le site affiche une page vide en production)

**Périmètre MVP défini lors de cet audit :**
- Seed éditorial : 100 mots validés en DB, min 1 exemple par mot
- Routes publiques : /, /mots, /mots/[slug], /mots/lettre/[lettre], /blog, /blog/[slug], /proposer (auth), /connexion
- Auth : inscription + connexion email/password via Better Auth
- Modération : dashboard fonctionnel pour valider/rejeter propositions
- Citabilité : Schema.org DefinedTerm par fiche mot, OG image dynamique par mot

**Déporté post-MVP :**
- Votes (VoteSection visible mais à désactiver jusqu'à 500 users actifs)
- Dashboard stats avancées
- Score de popularité affiché publiquement
- Gamification (badges, classements)
- Page /a-propos (dans la nav mais route absente)

**Features notables déjà livrées :**
- Stack complète : Next.js 16, Prisma/PostgreSQL, Better Auth, Tailwind 4, Docker
- Schéma Prisma complet pour V1.5 (votes, modération, rôles, score popularité)
- Dashboard multi-rôles avec shell Sidebar, pages mots/modération/stats/users/logs/propositions/profil
- ShareButton avec UTM + Web Share API
- Proposer form avec live preview
- Routing public/dashboard isolé proprement
- API REST pour mots (GET/POST avec pagination curseur, vote, slug)
- Full-text search PostgreSQL activé dans le schéma

**Infrastructure gap critique :**
- Pas de Schema.org DefinedTerm sur les fiches /mots/[slug]
- Pas d'OG image dynamique par mot
- Page /a-propos dans la nav mais route absente → lien mort
- Metadata homepage ment : "+400 mots" alors que base vide
